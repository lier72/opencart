Cause: Tables with UNIQUE keys (not PRIMARY KEY) failed with INSERT ... ON DUPLICATE KEY UPDATE
       Example: ocus_odoo_client_map has UNIQUE KEY on odoo_client_id
       ON DUPLICATE KEY UPDATE only handles PRIMARY KEY conflicts
Fix:   Added automatic detection of unique keys (lines 406-419)
       If table has unique keys → use REPLACE INTO instead of INSERT

ISSUE 3: Missing PRIMARY KEY in created tables (ocus_odoo_config)
Error: Duplicate rows with id=0 inserted into ocus_odoo_config
Cause: Table was created using CREATE TABLE ... AS SELECT which DOES NOT copy:
       ✗ PRIMARY KEY constraints
       ✗ AUTO_INCREMENT attributes
       ✗ UNIQUE keys, FOREIGN keys, Indexes
       ✗ Default values
       Used: CREATE TABLE `a1627-unqs-oc3`.`ocus_odoo_config` AS
             SELECT * FROM `a1627-unqs-oc`.`ocus_odoo_config`;
       Old DB: PRIMARY KEY (id), AUTO_INCREMENT
       New DB: No PRIMARY KEY, no AUTO_INCREMENT → id defaulted to 0
Result: REPLACE INTO could not detect duplicates, inserted new rows instead
Fix:   Manually corrected the table structure:
       DELETE FROM ocus_odoo_config WHERE id = 0;
       ALTER TABLE ocus_odoo_config
         ADD PRIMARY KEY (id),
         MODIFY COLUMN id INT UNSIGNED NOT NULL AUTO_INCREMENT;

       Method 2:
         SHOW CREATE TABLE old_db.table_name;
         -- Copy the output and execute in new database
         INSERT INTO new_db.table_name SELECT * FROM old_db.table_name;
