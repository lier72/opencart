# DaData Autocomplete - Journal3 Vue Integration Notes

## Important: Journal3 Uses Vue.js Single-Page Checkout

Journal3 theme uses a **Vue.js-based single-page checkout** system, not the standard OpenCart accordion checkout. This implementation has been specifically designed to work with Journal3's Vue architecture.

## How It Works with Vue

### 1. Vue Detection
The script automatically detects when Journal3's Vue QuickCheckout component is mounted:
- Waits for `window.QuickCheckout` to be available
- Falls back to standard mode if Vue is not detected (max 5 second wait)

### 2. Data Binding
When Vue is detected, the script:
- Directly updates Vue's reactive `order_data` object
- Works with Vue's `v-model` bindings
- Automatically triggers Vue's `save()` method to sync with backend

### 3. Field IDs Used
The autocomplete attaches to these input fields:
- **Payment Address:** `#input-payment-address-1`
- **Payment City:** `#input-payment-city`
- **Payment Postcode:** `#input-payment-postcode`
- **Shipping Address:** `#input-shipping-address-1`
- **Shipping City:** `#input-shipping-city`
- **Shipping Postcode:** `#input-shipping-postcode`

These IDs are generated by Journal3's Vue templates in:
`catalog/view/theme/journal3/template/journal3/checkout/address.twig`

## Template Structure

### Main Checkout Template
**File:** `catalog/view/theme/journal3/template/journal3/checkout/checkout.twig`
- Contains Vue template: `<template id="quick-checkout">`
- Includes blocks: `{{ payment_address_block }}`, `{{ shipping_address_block }}`
- Vue instance data: `window['_QuickCheckoutData']`

### Address Template
**File:** `catalog/view/theme/journal3/template/journal3/checkout/address.twig`
- Uses Vue directives: `v-model`, `v-if`, `v-for`
- Binds to: `order_data.{{ type }}_address_1`, `order_data.{{ type }}_city`, etc.
- Dynamic rendering based on address type (payment/shipping)

## Vue Integration Code

### Updating Vue Data
```javascript
if (window.QuickCheckout && window.QuickCheckout.order_data) {
    // Update address
    window.QuickCheckout.order_data[addressType + '_address_1'] = addressValue;

    // Update city
    window.QuickCheckout.order_data[addressType + '_city'] = cityValue;

    // Update postcode
    window.QuickCheckout.order_data[addressType + '_postcode'] = postcodeValue;

    // Trigger save to backend
    window.QuickCheckout.save();
}
```

### Zone/Region Matching
```javascript
// Set country to Russia
window.QuickCheckout.order_data[addressType + '_country_id'] = russiaCountryId;

// Wait for zones to load, then match
var zones = addressType === 'payment' ?
    window.QuickCheckout.payment_zones :
    window.QuickCheckout.shipping_zones;

// Match zone by name
zones.forEach(function(zone) {
    if (zone.name.indexOf(regionName) !== -1) {
        window.QuickCheckout.order_data[addressType + '_zone_id'] = zone.zone_id;
    }
});
```

## Debugging

### Check Vue Instance
Open browser console and type:
```javascript
window.QuickCheckout
```
You should see the Vue instance with properties like:
- `order_data` - Current form data
- `payment_zones` - Available payment address zones
- `shipping_zones` - Available shipping address zones
- `countries` - Available countries
- `save()` - Method to save data to backend

### Check Autocomplete Status
The script logs to console:
- `DaData Autocomplete: Initializing for Journal3 Vue checkout...`
- `DaData: Journal3 Vue QuickCheckout detected` (if Vue found)
- `DaData: Vue not detected, using standard mode` (if Vue not found)
- `DaData: Attaching to payment address field` (when input found)
- `DaData: Filling address fields` (when suggestion selected)

### Common Issues

#### 1. Vue Not Detected
**Symptom:** Console shows "Vue not detected, using standard mode"
**Solution:**
- Ensure you're on the actual checkout page
- Check that Journal3 checkout is enabled (not standard OpenCart)
- Vue takes time to mount, script waits up to 5 seconds

#### 2. Fields Not Auto-Filling
**Symptom:** Suggestions appear but clicking doesn't fill fields
**Solution:**
- Open console and check `window.QuickCheckout.order_data`
- Verify the property names match (e.g., `payment_address_1`)
- Check if Vue's `save()` method is being called

#### 3. Zone Not Matching
**Symptom:** Address and city fill, but region/zone doesn't
**Solution:**
- Check `window.QuickCheckout.payment_zones` or `shipping_zones`
- Verify zone names in OpenCart match DaData region names
- Russia must be selected as country first (country_id typically 176)

## Performance Considerations

### Vue Reactivity
- Direct updates to `order_data` trigger Vue's reactive system
- Changes are immediately reflected in the UI
- `save()` method syncs with backend via AJAX

### API Rate Limiting
- Each keystroke (after 3 chars) = 1 DaData API request
- With Vue's real-time sync, consider increasing typing delay
- Edit line 68: `var doneTypingInterval = 300;` → increase to 500ms
